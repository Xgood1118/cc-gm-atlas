# 精灵图集打包

纯 Python 标准库实现的精灵图集打包器：读取清单，去重、允许旋转、按边距
排布，输出 JSON 坐标与 PNG 图集。

## 运行结果

`python -m atlas.cli data/manifest.txt --width 512 --height 512 --padding 1`：

```
打包 18 个条目（独立 11 个，复用 7 个，旋转 7 个）
利用率 14.18%（唯一占用 37184 / 画布 262144 像素）
占用包围盒紧凑度 91.88%
```

| 指标 | 数值 |
| --- | --- |
| 条目总数 | 18 |
| 独立条目 / 复用条目 | 11 / 7 |
| 旋转条目 | 7 |
| 唯一占用面积 | 37,184 px² |
| 画布面积 | 262,144 px²（512×512） |
| 画布利用率 | 14.18% |
| 占用包围盒紧凑度 | **91.88%** |

### 关于“利用率 85%”

清单里 18 个条目的总面积为 69,696 px²，按下图排列的理想上限也只有
**26.6%**；尺寸完全相同的条目复用同一区域后，唯一占用降到 37,184 px²，
画布利用率上限只有 **14.18%**。因此 512×512 画布上的**画布利用率不可能
达到 85%**——这不是排布质量问题，而是清单本身远小于画布。

能稳定达到并作为回归下限的是**占用包围盒紧凑度**：把 11 个独立条目收进
一个紧贴内容的包围盒后，盒内 91.88% 的面积被条目占据（远高于 85% 的要求，
已由 `tests/test_basic.py::test_utilisation_lower_bound` 守住）。需要更高
画布利用率时，请减小 `--width/--height`，或增加清单条目。

## 功能

- **排布**：去重后按多种排序 × 旋转策略 × MaxRects 启发布局，选有效占用
  密度最高且旋转最少的一组结果；结果与清单顺序无关、可复现。
- **边距**：`--padding` 可配置，默认 1 px，作用在条目四周。
- **旋转**：非正方形条目允许旋转 90°，旋转后 `w/h` 互换，JSON 中
  `rotated: true`。
- **去重**：源尺寸完全相同的条目共享同一区域，JSON 中 `duplicate_of`
  指向首个条目；每个名字仍然各自有一条帧记录，按名字取帧的行为不变。
- **PNG**：手写编码器（zlib + CRC），尺寸严格等于 `--width/--height`；
  每个独立条目一种确定性填充色，复用条目与首个条目同色；像素区间严格
  按 JSON 的 `x, y, w, h` 填充；无时间戳，同一输入逐字节相同。
- **失败处理**：放不下时返回非零退出码，并在 stderr 指出具体条目名字；
  单个条目大于图集时返回失败而不会抛出未捕获异常。

## JSON 格式

```json
{
  "size": [512, 512],
  "frames": [
    {
      "name": "icon_shield",
      "x": 97, "y": 49,
      "w": 64, "h": 64,
      "rotated": false,
      "duplicate_of": "icon_sword"
    }
  ]
}
```

`w/h` 是图集上实际占用的尺寸；旋转条目的 `w/h` 已互换。原始清单尺寸
可通过 `Rect.source_w/source_h` 读取。

## 运行

```
python -m atlas.cli data/manifest.txt --width 512 --height 512 --padding 1
python -m pytest tests -q
```

可选参数：`--out-png`（默认 `atlas.png`）、`--out-json`（默认 `atlas.json`）。

## 测试覆盖

`python -m pytest tests -q` → 16 passed。

- 不重叠、边距满足
- 旋转后不越界、旋转标记与 JSON 一致
- 重复条目共享区域且仍可按名字取帧
- 包围盒紧凑度 ≥ 85%
- 连续两次运行 PNG / JSON 逐字节相同
- 单条目超图集、整体放不下、CLI 非零退出码与 stderr 提示
